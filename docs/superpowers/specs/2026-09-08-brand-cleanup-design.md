# Codex助手品牌整理与资源重制设计说明

- 日期：2026-09-08
- 状态：待审阅
- 范围：方案 B，保留产品名称，清理开发痕迹并重制品牌资源

## 目标

在保留“Codex助手”产品名称、现有用户认知和核心功能的前提下，降低项目中不必要的复制感与历史开发痕迹，形成一致、独立、可维护的品牌表达。兼容 OpenAI Codex 的技术事实继续保留，但不把第三方产品名称当作本项目的视觉品牌。

## 不变项

- 产品名称继续使用“Codex助手”。
- 保留与 OpenAI Codex 的必要兼容说明，不伪造兼容范围。
- 保留 APINest、自定义模型、历史配置迁移、主题注入、本地适配器等功能。
- 不删除或改写真实的第三方版权、许可和来源信息。
- 不引入远程授权、激活、版本检查、错误上报或其他联网依赖。
- 保持现有本地数据目录和内部配置键兼容，避免升级后丢失配置。

## 清理范围

### 文字与文档

- 删除或改写“优化UI与品牌清理”等内部过程性措辞。
- 统一 README、官网、用户手册、AGENTS 和界面中的产品名称写法。
- 将重复的 Codex/OpenAI 表述收敛到产品定位、兼容性说明和技术文档中。
- 移除“抄袭、仿制、匹配某设计稿”等容易暴露开发过程的表述。
- 保留准确的商标免责和兼容性说明。

### 内部命名

- 将面向用户或构建产物中出现的 `CodexSwitch`、`CodexHelper` 等旧内部品牌统一调整为“Codex助手”或中性模块名。
- 对本地数据目录、配置键和历史 provider 标识不做破坏性重命名；如必须保留旧键，增加注释或兼容映射，而不是迁移时直接删除。
- 检查应用标题、窗口标题、日志提示、安装器元数据、注册表路径和构建脚本中的命名一致性。

### 品牌资源

- 重新制作或调整 `logo.svg`、应用图标、品牌文字图片和吉祥物资源，使其形成独立的视觉系统。
- 应用内、官网和安装包使用同一套主 Logo、深浅色品牌文字和图标导出物。
- APINest 标识作为第三方服务商标识单独处理，不与本项目主品牌混用；若无法确认使用授权，优先改为纯文字标识。
- 对主题背景和插画资源检查来源；来源不清或授权不明确的图片不通过删除说明来掩盖，而是保留准确说明或替换为可确认来源的资源。

## 命名策略

| 场景 | 统一表达 |
|---|---|
| 产品名称 | Codex助手 |
| 英文窗口或构建标识 | Codex Assistant，只有在现有平台字段要求英文时使用 |
| 本地适配器内部标识 | 继续保留历史标识以兼容既有配置 |
| 兼容关系 | OpenAI Codex 兼容适配器，或更准确的实际能力描述 |
| 第三方服务商 | APINest，按服务商身份单独展示 |
| 旧构建标识 | 仅作为兼容和迁移用途保留，不再作为可见主品牌 |

## 实施顺序

1. 扫描所有可见品牌文本、内部命名、资源引用和打包入口，建立修改清单。
2. 先处理文档、界面文案和内部可见标识，保持功能代码不变。
3. 重制主 Logo、图标、品牌文字和吉祥物，并同步应用、官网和构建脚本引用。
4. 审核第三方来源、主题 manifest 和 `NOTICE`，修正过宽或不准确的版权表述。
5. 更新静态检查规则，确认旧内部品牌只存在于必要的兼容路径。
6. 编译、运行核心测试、检查资源引用，并分别构建 macOS 和 Windows 包。
7. 检查安装包内容、应用标题、图标、文档和版本信息的一致性。

## 验收标准

- GitHub 当前分支可见内容中不再出现“优化UI与品牌清理”等过程性措辞。
- 用户可见界面、官网、README、用户手册和安装包元数据统一使用“Codex助手”。
- `CodexSwitch`、`CodexHelper` 等旧品牌不再作为用户可见主品牌出现；必要的兼容键仍可正常工作。
- Logo、图标、品牌文字和吉祥物在应用与官网中一致，且不再使用明显的旧资源引用方式。
- Codex/OpenAI 兼容说明仍准确，商标免责和第三方许可信息没有被删除或伪造。
- 本地配置、历史 provider、主题功能、适配器和会话迁移行为不受影响。
- `python3 -m py_compile src/*.py` 通过。
- `python3 src/tests/test_core.py` 全部通过。
- macOS 与 Windows 构建成功，包内不含激活、后台管理或远程授权组件。
- 变更不会自动重写 Git 历史；如后续确需处理历史提交信息，另行确认并单独设计迁移方案。

## 风险与取舍

- 保留“Codex助手”意味着产品仍会与 Codex 产生关联，因此本设计重点是清理复制感和旧内部品牌，而不是隐藏真实兼容关系。
- 更换 Logo、图标和吉祥物会改变用户视觉识别，需要同步更新安装包和官网资源。
- 修改安装器注册表路径或数据目录可能影响升级，因此本轮只调整可见元数据，保留历史数据路径和配置键。
- 来源不明的主题图片可能无法通过代码修改彻底解决；应优先替换或保留准确来源说明，而不是删除免责声明。
- GitHub 已发布的旧 Release 不在本轮自动覆盖；实现完成并通过验证后，再决定是否发布新的 patch 版本。
