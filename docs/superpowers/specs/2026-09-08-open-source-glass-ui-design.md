# 开源化与玻璃风客户端改造设计

## 背景

项目当前包含客户端本地适配器、激活码客户端逻辑、独立管理后台和多个内置服务商模板。目标是将项目改造成安装后直接可用的开源客户端，移除服务端授权依赖，并在不改变现有信息架构的前提下优化为更精致的玻璃风界面。

## 目标

- 安装后无需激活码、设备绑定或网络授权即可使用。
- 移除客户端到激活服务器的请求、激活弹窗和启动前授权拦截。
- 移除独立管理后台和服务端部署相关内容，客户端仍保留本地控制 API。
- 新增模型时仅提供 `APINest` 与 `自定义` 两个服务商选项。
- 保留旧配置和已保存模型的兼容性，避免用户升级后丢失模型配置。
- 在现有页面结构、品牌色和功能模块基础上，统一升级为深色玻璃风。

## 非目标

- 不重写适配器协议转换、主题注入、Token 统计和 Codex 配置切换逻辑。
- 不改变 APINest 上游接口协议或 API Key 的本地存储方式。
- 不将项目改造成云端 SaaS，也不新增账号系统。
- 不强制删除用户本地已有的激活缓存文件，只是不再读取或依赖它。

## 功能设计

### 授权移除

启动、切换模型、保存配置和启动适配器均不再调用激活状态检查。`/api/activation/status`、`/api/activation/activate` 等客户端接口移除；前端删除激活遮罩、激活输入、设备码展示和相关错误处理。`src/activation.py` 不再被生产代码导入，可删除该模块；如果为兼容外部调用而保留，应明确标记为废弃且不执行网络请求。

### 服务端移除

删除 `admin/` 管理后台及其数据库、API、部署脚本和服务端文档。客户端错误上报不再发送到远端激活服务器，错误日志继续写入本地数据目录。README、发布说明和项目结构同步改为纯客户端开源项目说明。

### 服务商选择

新增模型表单只显示两个选项：

- `APINest`：使用内置 APINest Base URL 和模型预设，可手动补充模型名称。
- `自定义`：手动填写 OpenAI 兼容 Base URL、模型名称和 API Key。

旧服务商配置不删除。已存在的模型在模型列表中继续显示和编辑；新增模型不再从旧服务商模板中选择。保存接口仍使用现有 provider、model、url、api_key 数据结构，降低迁移风险。

## UI 设计

### 结构

保留现有单文件前端、侧边栏导航、首页、模型中心、统计、主题和设置模块。取消激活遮罩后，应用打开直接进入主工作台。首页优先展示服务状态、当前模型、快速操作和用量摘要。

### 玻璃视觉

- 页面背景：深色多层渐变与低强度蓝紫/青色光晕。
- 侧边栏：半透明深色玻璃，使用 `backdrop-filter: blur()`，保持导航层级清晰。
- 内容卡片：半透明白色填充、低透明度边框、柔和阴影和统一圆角。
- 主操作：服务启动/停止按钮使用品牌色光晕和清晰的成功、警告、错误状态。
- 交互：卡片 hover 轻微上移和边框增亮，避免过度动画。
- 可读性：正文、辅助文字和状态颜色满足足够对比度；玻璃效果不可作为信息传达的唯一手段。
- 兼容性：为不支持背景模糊的环境提供半透明纯色回退。

### 模型表单

服务商选择使用两个并列玻璃选项卡。选择 `APINest` 时显示预设地址和模型下拉；选择 `自定义` 时显示 Base URL 和模型名称输入。API Key 输入、连通性测试、保存按钮沿用现有行为，仅调整布局、间距、层次和状态反馈。

## 数据流

1. 客户端启动并读取本地配置，不执行激活检查。
2. 用户在模型表单选择 APINest 或自定义并填写凭据。
3. 前端调用本地 `/api/config/save` 保存模型配置。
4. 用户启动适配器，本地控制 API 直接执行启动逻辑。
5. 适配器按现有流程将 Codex Responses 请求转换并转发到配置的 OpenAI 兼容上游。
6. 统计和错误信息继续本地保存，不向远端服务发送数据。

## 错误处理

- 缺少 API Key、Base URL 或模型名时，继续在本地表单提示，不发起请求。
- APINest 或自定义上游不可达时，沿用现有适配器错误格式和本地日志。
- 激活相关接口被旧客户端调用时，可返回明确的“授权功能已移除”响应，或直接删除接口并确保新客户端不再调用。
- 旧模型配置读取失败时，不阻塞应用启动；展示可恢复的空状态并保留原始本地文件。

## 兼容与迁移

- 不主动删除 `~/.codex-helper/activation.json`、`server.json` 等用户文件，避免误删用户数据。
- 不迁移或覆盖已有 provider 配置；仅限制新增模型的 UI 选项。
- 打包配置不再包含 `admin/`、服务端数据库和服务端运行时文件。
- 版本号按项目约定同步更新 `build_dmg.sh` 和 `web/index.html` 的显示及变量。

## 测试验收

- 无激活文件、无网络时，客户端可以打开、保存模型并启动本地适配器。
- 启动过程不访问激活服务器，不显示激活弹窗或设备码。
- 新增模型服务商下拉仅包含 `APINest`、`自定义`。
- APINest 模型可保存、编辑、测试和启动。
- 自定义 Base URL、模型名和 Key 可保存、编辑、测试和启动。
- 已有旧服务商模型仍可展示、切换和使用。
- 玻璃风在 macOS 和不支持模糊的环境下均有可用回退样式。
- Python 语法检查、现有核心测试和打包验证通过。
- 发布包中不含 `admin/` 服务端目录及激活运行时依赖。
